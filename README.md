# whats_cooking
> **Women in Data — Datathon 2026** | *Food Systems Data Analysis Challenge*

This repository houses our team's end-to-end data pipeline and analysis exploring how livestock production growth and manure-related emissions can be transformed into actionable biogas energy solutions.

---

## 📋 Analysis Workflow & Storyline

The project follows a sequential narrative across three distinct parts:

### Part 1: Livestock Growth
* **Objective:** Identify countries with the largest increase in livestock production over the last 10 years.
* **Outputs:** Livestock quantity, percentage increase, and density metrics by country.

### Part 2: Manure & Emissions
* **Objective:** Quantify the environmental burden generated by key livestock types per country.
* **Outputs:** Manure and emissions volumes for chickens, cattle, and pigs.

### Part 3: Waste-to-Energy Solution
* **Objective:** Assess current biogas usage and model renewable energy potential in high-priority target sites.
* **Outputs:** Biogas yield potentials and the estimated number of households powered by country and livestock type.

---

## ⚙️ Data Standards & Schema Rules

To ensure seamless joins across all parts of the analysis, all generated datasets must strictly adhere to these guidelines:

* **Primary Key:** `Area Code (M49)` must be present in every table.
* **Time Dimension:** Include `Year` across all output tables.
* **Livestock Taxonomy Normalization:** Standardize all animal names to a common naming convention across datasets.
  * *Example:* The *Crops and Livestock Products* table lists `Stocks` with items like `"Cattle, dairy"` and `"Cattle, non-dairy"`. These must be mapped and aggregated to a single value: `"Cattle"`.

## 📊 Power BI Collaboration Strategy

Because Power BI binary files (`.pbix`) cannot be cleanly merged by Git when multiple people make edits, use one of the following approaches:

* **Option A: Power BI Developer Mode (`.pbip`)** *(Recommended)*
  Save work as a **Power BI Project (`.pbip`)**. This breaks the file into human-readable JSON/text files that Git can track, diff, and merge seamlessly.
* **Option B: Separate Reports with a Shared Semantic Model**
  * Each team member builds a distinct report for their specific part using the cleaned datasets in `data/processed/`.
  * Alternatively, publish a single **Power BI Shared Semantic Model** to the Power BI Service so all team members can build separate visual reports connected live to the same dataset.
